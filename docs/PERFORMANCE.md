# Производительность

В демо возможны задержки в симуляторе. **Профилирование и оптимизация перед передачей не проводились; стабильные 60/120 FPS не подтверждены.** Расчётные проверки движения не измеряют время CPU/GPU-кадра.

По исходникам видны кандидаты для измерения:

| Место | Что проверить |
| --- | --- |
| `LiquidChatsApp.swift`: общий `TimelineView` | Частые обновления большого дерева, включая скрытый список чатов; отделить постоянно движущуюся сцену от истории и статичных контролов |
| `PartyOrbitPhysics.update` | Расчёты и запись состояния при нулевых смещениях; останавливать интеграцию после покоя, сохраняя непрерывность при новом жесте |
| `PortalDiscoBall` | Создание геометрии при первом показе, RealityKit update и качество сетки; оценить предварительную подготовку и reuse |
| `DiscoLights`, `partyRipple`, `messageEdgeBlur` | Полноэкранные проходы, blur и GPU-нагрузка при одновременной работе; измерять эффекты по одному |
| `PartyEmojiShower` | До трёх всплесков по 120 элементов; проверить пик при повторных двойных нажатиях и очистку после завершения |
| Медиатека | Память миниатюр, загрузка из iCloud и отмена при уходе. Сейчас используются небольшие миниатюры и изображение до 1200 px для аватарки |

## План измерений

1. На одной версии Xcode сравнить Debug и Release без отладчика; записать модель Mac/устройства, версию ОС, размер окна, сценарий и количество элементов. Не сравнивать разные сборки и сценарии как один benchmark.
2. В Instruments использовать SwiftUI, Time Profiler и Hitches. Для GPU подключить подходящий Metal/System Trace инструмент. [Инструкция Apple](https://developer.apple.com/documentation/Xcode/understanding-and-improving-swiftui-performance).
3. Измерить вход в чат, первый Start, 10 секунд активной сцены, прокрутку истории, перетаскивание, три быстрых всплеска и смену темы. Контролировать память после нескольких входов/выходов.
4. Применять изменения по одному и повторять тот же сценарий. Проверять не только среднее FPS, но и пропуски кадров, длительность пиков и память. Бюджет одного кадра — примерно 16,7 мс при 60 Гц и 8,3 мс при 120 Гц.
5. Повторить в Release на настоящем поддерживаемом iPhone, включая менее производительное устройство, Reduce Motion и возврат из фона.

Сначала сокращайте лишние обновления и работу в покое. Частоту декоративных эффектов, число частиц или детализацию шара меняйте после замеров и проверки внешнего вида. Для production нужна остановка анимаций при невидимом чате/неактивной сцене; перенос общего таймера демо без адаптации не является завершённой оптимизацией.
